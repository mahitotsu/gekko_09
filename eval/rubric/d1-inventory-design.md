# 採点基準: 在庫予約の同時実行対策の設計（docs/inventory-design.md）

各項目を、文書に書かれていれば 1、書かれていない・誤っていれば 0 とする。

- I1: 原因として、reserve が在庫を読んでから書くまでの間（await の間）に、別の reserve が同じ在庫を読めることを挙げている
- I2: store のインターフェース（get/set）を変えない対策になっている
- I3: 同じ商品（sku）への reserve を1つずつ順に実行する仕組み（商品ごとのロックや待ち行列など）を提案している
- I4: 別の商品への予約は並行して進められることに触れている
- I5: release も同じ仕組みの対象にする必要があることに触れている
- I6: 処理の途中で例外が起きても、ロックや待ち行列が詰まらないようにする方法に触れている
- I7: この対策は1つのプロセスの中でしか効かず、複数のプロセスやサーバーでは store 側の仕組みが必要になるという限界を書いている
- I8: 同時に予約したときに在庫を超えないことを確かめるテストの方針を書いている
- I9: 実装をしていない（文書だけ。コードの変更を前提にした手順の説明は可）
