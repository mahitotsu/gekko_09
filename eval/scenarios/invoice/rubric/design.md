# 採点基準: 設計（docs/design.md）

各項目を、文書に書かれていれば 1、書かれていない・誤っていれば 0 とする。

- D1: 入出力（引数・ファイル）と計算の処理を分けたモジュール構成になっている
- D2: 入力データの検証を、出力ファイルを書く前に行う流れになっている（終了コード 2 のときに出力が残らない）
- D3: 請求期間の求め方が、末日締め・日付締め・1月分（前年12月から）のいずれも正しく書かれている
- D4: 注文日の時点で有効な価格の行を選ぶ方法（適用開始日が注文日以前でもっとも新しい行）が書かれている
- D5: 単価の計算で、特約店の 10% 引き（切り捨て）を数量割引より先に適用する順になっている
- D6: 送料の判定が注文ごとで、8% の商品を含む税抜の合計で 10,000 円以上を判定し、返品の影響を受けない
- D7: 返品の金額を元の明細（元の注文日の価格、割引の後）から按分して切り捨てる計算が書かれている
- D8: 返品の明細数量の累計が注文数量を超えないかの検証が書かれている
- D9: 消費税を税率ごとの合計から1回だけ求め、端数処理の方法ごとの計算と、マイナスの場合の扱いが書かれている
- D10: 金額の計算で浮動小数点の誤差を避ける方法（整数演算など）に触れている
- D11: 繰越（前月分の前回請求額と期間内の入金）と、請求書を発行しない条件の判定が書かれている
- D12: 出力の並び順（請求書は顧客コード順、明細は日付順で同じ日付は注文が先・返品が後、注文の中は入力の順で送料は最後）が書かれている
- D13: エラー処理で、引数の誤り（1）と入力データの不整合（2）を区別している
- D14: 要件（最終の決定）と矛盾する記述がない
