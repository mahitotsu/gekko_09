# 請求書発行システム 連携仕様書

第4版（2026年9月3日）　情報システム室

第3版からの変更（変更管理会議 2026年9月3日）: 商品マスタの適用開始日（価格改定）、返品データ・入金データ・前回請求額データの入力、請求書の列（前回請求額、入金額、繰越額、返品件数、今回の請求額）、請求明細の列（明細の種類、日付）、請求書を発行する条件、入力データの不整合の追加。

## 1. 概要

受注データ・返品データ・入金データ・前回請求額データ・顧客マスタ・商品マスタの CSV を読み、指定した対象月の請求書と請求明細の CSV を出力するコマンドである。計算の規則は請求業務規程（2026年9月1日改定）と、議事録（第2回〜第4回）の決定による。

## 2. 実行環境

- Node.js 24 以降。外部のパッケージは使わない。
- 入口のファイルは `src/cli.js` とする。

## 3. コマンド

```
node src/cli.js --month <対象月> --data <入力ディレクトリ> --out <出力ディレクトリ>
```

| 引数 | 内容 |
| --- | --- |
| `--month` | 対象月。`YYYY-MM` の形式（例: `2026-09`） |
| `--data` | 入力ディレクトリ。5章の6つのファイルを置く（データがないファイルも、見出し行だけで置く） |
| `--out` | 出力ディレクトリ。なければ作る。`invoices.csv` と `invoice_lines.csv` を書く（同名のファイルは上書きする） |

終了コード:

| コード | 意味 |
| --- | --- |
| 0 | 成功 |
| 1 | 引数の誤り（引数が足りない、`--month` の形式が不正など）。標準エラー出力に理由を出す |
| 2 | 入力データの不整合（3.1）。出力ファイルは作らない。標準エラー出力に、問題のある行を示す番号を含むメッセージを出す |

### 3.1 入力データの不整合

次のいずれかに当たる行が1つでもあれば、終了コード 2 で終了する。対象期間外の行や取消の注文も含め、すべての行を調べる。メッセージには、注文は注文番号、返品は返品番号、入金は入金番号、前回請求額は顧客コードを含める。

| 対象 | 不整合 |
| --- | --- |
| 受注データ | 顧客コードが顧客マスタにない／商品コードが商品マスタにない／注文日の時点で有効な価格がない |
| 返品データ | 注文番号が受注データにない／その注文にその商品の明細がない／その注文が取消されている／同じ明細の返品数量の合計が注文数量を超える（超えた時点の返品の返品番号を示す） |
| 入金データ | 顧客コードが顧客マスタにない |
| 前回請求額データ | 顧客コードが顧客マスタにない |

## 4. ファイルの形式（入出力共通）

- 文字コードは UTF-8（BOM なし）。1行目は見出し行。区切りはカンマ。
- フィールドにカンマ、改行、ダブルクォートは含まれない（クォートはしない）。
- 出力の改行は LF とし、最後の行の後にも改行を置く。
- 金額と数量は整数で、桁区切りのカンマは付けない。マイナスは先頭に `-` を付ける。日付は `YYYY-MM-DD`。

## 5. 入力

### 5.1 customers.csv（顧客マスタ）

| 列 | 内容 |
| --- | --- |
| customer_id | 顧客コード |
| name | 顧客名 |
| closing_day | 締め日。`1`〜`28` の数字、または `末`（末日締め） |
| zone | 配送地域。`A`、`B`、`C` |
| rank | `一般` または `特約店` |
| rounding | 消費税の端数処理。`切り捨て`、`四捨五入`、`切り上げ`、または空欄（切り捨て） |

### 5.2 products.csv（商品マスタ）

同じ商品コードの行が、適用開始日ごとに複数あることがある（価格改定）。

| 列 | 内容 |
| --- | --- |
| product_id | 商品コード |
| name | 商品名 |
| unit_price | 単価（税抜、円） |
| tax_rate | 消費税率。`10` または `8` |
| valid_from | 適用開始日。この日以降の注文に、この行の単価・税率・商品名を使う |

### 5.3 orders.csv（受注データ）

1行が注文の1明細。1つの注文が複数の行になる。同じ注文番号の行は、order_date、customer_id、status が同じである。1つの注文に同じ商品の行は1つまで。

| 列 | 内容 |
| --- | --- |
| order_id | 注文番号 |
| order_date | 注文日 |
| customer_id | 顧客コード |
| product_id | 商品コード |
| quantity | 数量 |
| status | `確定` または `取消` |

### 5.4 returns.csv（返品データ）

| 列 | 内容 |
| --- | --- |
| return_id | 返品番号 |
| return_date | 返品日 |
| order_id | 元の注文の注文番号 |
| product_id | 返品した商品の商品コード |
| quantity | 返品数量（正の整数） |

### 5.5 payments.csv（入金データ）

| 列 | 内容 |
| --- | --- |
| payment_id | 入金番号 |
| payment_date | 入金日 |
| customer_id | 顧客コード |
| amount | 入金額（円） |

### 5.6 balances.csv（前回請求額データ）

| 列 | 内容 |
| --- | --- |
| customer_id | 顧客コード |
| month | 請求の対象月（`YYYY-MM`） |
| amount | その月の請求書の今回の請求額（円） |

対象月の前月の行を、前回の請求額として使う。前月の行がない顧客は 0 円とする。

## 6. 出力

### 6.1 invoices.csv（請求書）

請求書を発行する顧客ごとに1行。顧客コードの昇順。請求期間内に注文も返品もなく、前回の請求額も入金もない顧客の行は出さない。誰にも請求書がない場合は見出し行だけのファイルになる。

| 列 | 内容 |
| --- | --- |
| invoice_no | 請求書番号（規程 第2条） |
| customer_id | 顧客コード |
| customer_name | 顧客名 |
| period_start | 請求期間の初日 |
| period_end | 請求期間の末日 |
| previous_balance | 前回の請求額 |
| payment | 請求期間内の入金額の合計 |
| carried_over | 繰越額（previous_balance − payment） |
| order_count | 請求期間内の対象の注文の数（注文番号の数） |
| return_count | 請求期間内の返品の数（返品番号の数） |
| subtotal_10 | 10% 対象の金額の合計（税抜、送料と返品を含む） |
| tax_10 | 10% の消費税額 |
| subtotal_8 | 8% 対象の金額の合計（税抜、返品を含む） |
| tax_8 | 8% の消費税額 |
| total | 今回の請求金額（subtotal_10 + tax_10 + subtotal_8 + tax_8） |
| total_due | 今回の請求額（carried_over + total） |

### 6.2 invoice_lines.csv（請求明細）

注文の明細、送料、返品の行。並び順は、請求書番号の昇順、その中で日付の昇順。同じ日付では、注文の明細（送料を含む）を先に注文番号の昇順で、返品を後に返品番号の昇順で並べる。1つの注文の中では、受注データの行の順に商品の明細を並べ、送料の行はその注文の最後に置く。

| 列 | 内容 |
| --- | --- |
| invoice_no | 請求書番号 |
| line_type | `商品`、`送料`、`返品` |
| order_id | 注文番号（返品の行は元の注文の注文番号） |
| date | 注文日（返品の行は返品日） |
| product_id | 商品コード。送料の行は `SHIPPING` |
| product_name | 商品名（元の注文の注文日の時点のもの）。送料の行は `送料` |
| quantity | 数量。送料の行は `1`、返品の行はマイナスの返品数量 |
| unit_price | 適用した単価（特約店は割引後、返品の行は元の明細の単価）。送料の行は送料の額 |
| amount | 金額（商品は数量割引の後、返品はマイナス）。送料の行は送料の額 |
| tax_rate | 税率（返品の行は元の明細の税率）。送料の行は `10` |
