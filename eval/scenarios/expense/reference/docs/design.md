# 経費精算システム 設計

要件: docs/requirements.md。外部パッケージなし、Node.js 24、ES モジュール。

## 1. モジュール構成

| ファイル | 役割 |
| --- | --- |
| `src/cli.js` | 引数の解析と検証、3つの入力の読み込みと検証、対象月の申請の審査の呼び出し、支払の集計、出力 |
| `src/expense.js` | 審査の規則（期限、宿泊費の上限、日当、明細の判定、承認経路、支払日）。入出力を持たない純粋な関数 |
| `src/csv.js` | CSV の読み書き（クォートなし、見出し行あり、出力は LF） |

## 2. データの流れ

1. 引数を検証する（足りない、`--month` が `YYYY-MM` でない → 終了コード 1）。
2. 3つの CSV を読み、全行を検証する（連携仕様書 3.1）。最初の不整合で、行の番号を含むメッセージを出して終了コード 2。出力の前に調べるので、ファイルは作られない。
3. 提出日が対象月の申請を申請番号の昇順に審査する（`reviewClaim`）。
4. 社員ごとに承認額を合計し、0 円より多い社員の支払の行を作る。
5. 出力ディレクトリを作り、3つの CSV を書く。

## 3. 審査の手順（expense.js）

- `daysBetween(from, to)`: UTC の日付の差（日数）。タイムゾーンや夏時間の影響を受けない。
- `lodgingCap(grade, place, date)`: 宿泊日が 2026-10-01 以降なら改定後の表（東京の一般・主任）、なければ基本の表。
- `dailyAllowance(grade, kind, days)`: 日額 × 日数、日帰りは日額の半分（日額はすべて偶数なので割り切れる）。
- `reviewItem(item, grade, submitDate)`: 連携仕様書 6.1 の順に判定し、{ 結果, 承認額, コード, 区分 } を返す。会議費は `金額 > 5000 × 人数` を整数で比べる（割り算をしない）。
- `reviewClaim(claim, items, employee, employees)`: 明細を明細番号の順に審査し、状態、申請額の合計、承認額の合計、承認経路を求める。接待費の有無は、却下されていない明細の区分（改めた後）で判定する。
- `approvalRoute(employee, employees, approved, hasEntertainment)`: 承認額 0 なら空。役員なら ACCT。それ以外は上長から始め、部長以上・役員を、経路の最後の承認者から上長をたどって探して加える。
- `paymentDate(month)`: 翌月25日の曜日を見て、土曜は24日、日曜は23日。12月分は翌年1月。

## 4. エラー処理

| 状況 | 動作 |
| --- | --- |
| 引数が足りない、`--month` の形式が不正、未知の引数 | 標準エラーに理由、終了コード 1 |
| 入力データの不整合 | 標準エラーに行の番号、終了コード 2、出力なし |

## 5. テスト方針

- `expense.js` の関数を単体で試す（期限の 60/61日と未来日、領収書の 999/1,000円と日当、宿泊費の改定の前日と当日、日当の半額と申請額が少ない場合、会議費の 5,000円ちょうどと超え、物品の 99,999/100,000円、承認経路の 5万円・30万円の境界と接待費と役員、支払日の土曜・日曜・12月）。
- CLI をサンプルデータで実行し、連携仕様書の例と比べる。入力データの不整合で終了コード 2 になり、出力がないことを確かめる。
