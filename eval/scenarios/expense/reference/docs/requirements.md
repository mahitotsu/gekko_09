# 経費精算システム 要件

根拠: 議事録（第1回 2026-06-11、第2回 2026-07-16、第3回 2026-08-27、第4回 2026-09-17）、経費精算規程（2026-10-01 改定）、連携仕様書 第4版。第3回で仕様が確定し、第4回の変更管理会議で変更が承認された。連携仕様書 第4版を正とする。

## 1. 目的と範囲

- 社員マスタ・申請・明細の CSV から、指定した月に提出された申請を規程どおりに審査し、申請ごと・明細ごとの結果と、社員ごとの支払額を出すコマンドラインツール。
- 範囲外: 海外出張の手当（第2回）、交通費の距離からの計算（第2回）、仮払い（第3回）。

## 2. 機能要件

### 2.1 コマンド

- `node src/cli.js --month YYYY-MM --data <入力> --out <出力>`。Node.js 24 以降、外部パッケージなし。終了コード: 0 成功、1 引数の誤り、2 入力データの不整合。
- 提出日が対象月の申請だけを審査する。

### 2.2 明細の審査（判定の順。最初に当てはまったものを結果とする。連携仕様書 6.1）

1. 利用日が提出日より後 → 却下 E02（第4回 決定4）。
2. 提出日 − 利用日 が 60日を超える → 却下 E01。60日ちょうどは期限内（第3回 決定1、第4回 決定4）。
3. 日当以外で、領収書が無く、1,000円以上 → 却下 E03（第3回 決定2）。
4. 物品で 100,000円以上 → 却下 E04（第3回 決定6）。
5. 宿泊費: 上限 = 1泊の上限（役職・地域、宿泊日で選ぶ）× 泊数。超えたら上限で一部承認 W01（第2回 決定1、第4回 決定1）。
   - 1泊の上限は規程の別表1。2026-10-01 以降の宿泊は、東京の一般 12,000円・主任 13,000円（それより前は 10,000円・11,000円）。
6. 日当: 上限 = 日額（一般 2,000、主任 2,500、課長 3,000、部長 4,000、役員 5,000）× 日数、日帰りは半額。超えたら上限で一部承認 W02。以下なら申請額（第2回 決定2、第4回 決定2）。
7. 会議費: 申請額が 5,000円 × 人数 を超えたら、区分を接待費に改め、申請額のまま承認 W03（第3回 決定3）。
8. 上のどれでもなければ承認。

### 2.3 申請の結果

- 状態: 全明細が却下なら却下、却下か一部承認が1つでもあれば一部承認、それ以外は承認。
- 承認額は明細の承認額の合計。申請額の合計には却下された明細も含める。

### 2.4 承認経路（第2回 決定3、第3回 決定4・5・7、第4回 決定3）

- 承認額で判定する（申請額ではない）。承認額が 0 円の申請には経路を付けない。
- 役員の申請は経理課長（ACCT）だけ。
- それ以外: 上長 → （承認額 5万円以上か、却下されていない接待費を含むなら）上長をたどって最初の部長以上（経路の最後がすでに部長以上なら不要） → （30万円以上で経路に役員がいなければ）たどって最初の役員。
- 却下された会議費は、区分を改めず、経路の判定にも使わない（第4回 確認事項）。

### 2.5 支払

- 社員ごとに、その月に審査した申請の承認額を合計し、0 円より多い社員に支払う。
- 支払日は翌月25日。土曜なら24日、日曜なら23日（第3回 決定8）。祝日は考えない（第4回 見送り）。

### 2.6 入力データの不整合（第3回 決定9、連携仕様書 3.1）

- 全行を調べ、最初の不整合で、問題の行の番号（社員番号・申請番号）を含むメッセージを出し、何も出力せず終了コード 2。
- 社員: 役職が規程にない、上長がいない（役員は上長が空でよい）。申請: 社員がいない、明細がない。明細: 申請がない、区分・金額・領収書・数・種別が正しくない。

### 2.7 出力

- claim_results.csv、item_results.csv、payments.csv。列・並び順・書式は連携仕様書 第4版 4章・7章のとおり。

## 4. 見送りの要望

- 海外出張の手当（第2回。別の規程で扱う）。
- 交通費を経路の距離から計算する（第2回）。
- 仮払い（第3回）。
- 宿泊費の超過分を日当の残りで相殺する（第4回）。
- 支払日の調整に祝日を含める（第4回）。
