# 経費精算システム 連携仕様書

第4版（2026年9月17日）　情報システム課

第3版からの変更（変更管理会議 2026年9月17日）: 東京の宿泊費の上限の改定（宿泊日で判定）、日当の上限の扱い、承認の金額の判定を承認額で行うこと、期限の数え方、却下された明細の扱いを明記。

## 1. 概要

社員マスタ・申請・明細の CSV を読み、指定した月に提出された申請を経費精算規程（2026年10月1日改定）と議事録（第2回〜第4回）の決定に従って審査し、申請ごとの結果、明細ごとの結果、社員ごとの支払額の CSV を出力するコマンドである。

## 2. 実行環境

- Node.js 24 以降。外部のパッケージは使わない。
- 入口のファイルは `src/cli.js` とする。

## 3. コマンド

```
node src/cli.js --month <対象月> --data <入力ディレクトリ> --out <出力ディレクトリ>
```

| 引数 | 内容 |
| --- | --- |
| `--month` | 対象月。`YYYY-MM` の形式。提出日がこの月の申請を審査する |
| `--data` | 入力ディレクトリ。`employees.csv`、`claims.csv`、`items.csv` を置く |
| `--out` | 出力ディレクトリ。なければ作る。`claim_results.csv`、`item_results.csv`、`payments.csv` を書く |

終了コード: 0 成功、1 引数の誤り（標準エラーに理由）、2 入力データの不整合（3.1。出力ファイルは作らない。標準エラーに、問題の行を示す番号を含める）。

### 3.1 入力データの不整合

対象月以外の申請も含め、すべての行を調べる。最初に見つかった不整合で終了する。

| 対象 | 不整合 | メッセージに含める番号 |
| --- | --- | --- |
| 社員 | 役職が5つ（一般・主任・課長・部長・役員）のどれでもない／上長が社員マスタにない（役員は上長が空でよい） | 社員番号 |
| 申請 | 社員が社員マスタにない／明細が1つもない | 申請番号 |
| 明細 | 申請がない／区分が6つのどれでもない／金額が0以上の整数でない／領収書が `有`・`無` でない／宿泊費・日当・会議費・接待費で数（泊数・日数・人数）が1以上の整数でない／宿泊費・日当で種別が正しくない | 申請番号 |

## 4. ファイルの形式

UTF-8（BOM なし）、1行目は見出し、区切りはカンマ、クォートなし（フィールドにカンマ・改行・ダブルクォートは含まれない）。出力の改行は LF で、最後の行の後にも改行を置く。金額は整数（桁区切りなし）、日付は `YYYY-MM-DD`。

## 5. 入力

### 5.1 employees.csv（社員マスタ）

| 列 | 内容 |
| --- | --- |
| employee_id | 社員番号 |
| name | 氏名 |
| grade | 役職。`一般`、`主任`、`課長`、`部長`、`役員` |
| manager_id | 上長の社員番号（役員の最上位は空） |
| department | 部署名 |

### 5.2 claims.csv（申請）

| 列 | 内容 |
| --- | --- |
| claim_id | 申請番号 |
| employee_id | 申請者の社員番号 |
| submit_date | 提出日 |

### 5.3 items.csv（明細）

| 列 | 内容 |
| --- | --- |
| claim_id | 申請番号 |
| item_no | 明細番号（申請の中の連番） |
| date | 利用日（宿泊費は宿泊を始めた日、日当は出張の初日） |
| category | 区分。`交通費`、`宿泊費`、`日当`、`会議費`、`接待費`、`物品` |
| amount | 申請額（円） |
| receipt | 領収書。`有` または `無` |
| count | 宿泊費は泊数、日当は日数、会議費・接待費は人数（申請者を含む）。ほかの区分は空 |
| kind | 宿泊費は地域（`東京`、`大阪`、`その他`）、日当は `日帰り` または `宿泊`。ほかの区分は空 |

## 6. 審査

### 6.1 明細の判定の順

明細ごとに、次の順に判定し、最初に当てはまったものを結果とする。

| 順 | 条件 | 結果 | コード | 承認額 |
| --- | --- | --- | --- | --- |
| 1 | 利用日が提出日より後 | 却下 | E02 | 0 |
| 2 | 提出日 − 利用日 が 60日を超える | 却下 | E01 | 0 |
| 3 | 日当以外で、領収書が無く、申請額が 1,000円以上 | 却下 | E03 | 0 |
| 4 | 物品で、申請額が 100,000円以上 | 却下 | E04 | 0 |
| 5 | 宿泊費で、申請額が 上限額 × 泊数 を超える | 一部承認 | W01 | 上限額 × 泊数 |
| 6 | 日当で、申請額が 日額 × 日数（日帰りは半額）を超える | 一部承認 | W02 | 日額 × 日数 |
| 7 | 会議費で、申請額が 5,000円 × 人数 を超える | 承認（区分を接待費に改める） | W03 | 申請額 |
| 8 | 上のどれでもない | 承認 | （空） | 申請額 |

### 6.2 申請の結果

- 状態: すべての明細が却下なら `却下`、却下か一部承認の明細が1つでもあれば `一部承認`、それ以外は `承認`（区分を改めただけの明細は承認として数える）。
- 承認額: 明細の承認額の合計。

### 6.3 承認経路

承認額が 0 円の申請には付けない。役員の申請は `ACCT`（経理課長）だけとする。それ以外は次のとおり。

1. 申請者の上長。
2. 承認額が 50,000円以上か、却下されていない接待費（区分を改めたものを含む）を含むなら、部長以上の承認者を加える。すでに経路の最後の承認者が部長以上なら加えない。加える場合は、経路の最後の承認者から上長をたどって最初に見つかる部長以上の社員とする。
3. 承認額が 300,000円以上で、経路に役員がいなければ、経路の最後の承認者から上長をたどって最初に見つかる役員を加える。

経路は社員番号を `>` でつなぐ（例: `E012>E010`）。

### 6.4 支払

社員ごとに、その月に審査した申請の承認額を合計し、0 円より多い社員に支払う。支払日は対象月の翌月25日で、土曜なら24日、日曜なら23日とする。

## 7. 出力

### 7.1 claim_results.csv（申請ごとの結果）

申請番号の昇順。

| 列 | 内容 |
| --- | --- |
| claim_id | 申請番号 |
| employee_id | 申請者の社員番号 |
| submit_date | 提出日 |
| status | `承認`、`一部承認`、`却下` |
| item_count | 明細の数 |
| claimed_total | 申請額の合計（却下された明細を含む） |
| approved_total | 承認額の合計 |
| route | 承認経路（なければ空） |

### 7.2 item_results.csv（明細ごとの結果）

申請番号の昇順、その中で明細番号の昇順。

| 列 | 内容 |
| --- | --- |
| claim_id | 申請番号 |
| item_no | 明細番号 |
| date | 利用日 |
| category | 区分（W03 の明細は `接待費`） |
| claimed | 申請額 |
| approved | 承認額 |
| result | `承認`、`一部承認`、`却下` |
| code | 6.1 のコード（なければ空） |

### 7.3 payments.csv（社員ごとの支払）

社員番号の昇順。支払がない社員の行は出さない。

| 列 | 内容 |
| --- | --- |
| employee_id | 社員番号 |
| name | 氏名 |
| amount | 支払額 |
| payment_date | 支払日 |
