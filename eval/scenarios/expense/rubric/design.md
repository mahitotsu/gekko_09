# 採点基準: 設計（docs/design.md）

各項目を、文書に書かれていれば 1、書かれていない・誤っていれば 0 とする。

- D1: 入出力と審査の規則を分けたモジュール構成になっている
- D2: 入力データの検証を、出力ファイルを書く前に行う流れになっている
- D3: 明細の判定を連携仕様書の順に行い、最初に当てはまったもので決める方法が書かれている
- D4: 日付の差（期限の日数）の求め方が、タイムゾーンなどの影響を受けない方法になっている
- D5: 宿泊費の上限を、宿泊日で版を選び、泊数を掛けて求める方法が書かれている
- D6: 日当の上限（日額 × 日数、日帰りは半額）と、申請額が少ない場合の扱いが書かれている
- D7: 会議費から接待費への区分の変更を、金額と人数の比較で判定する方法が書かれている
- D8: 承認経路を、承認額で判定し、上長をたどって部長以上・役員を探す方法が書かれている（役員の申請と、承認額 0 円の扱いを含む）
- D9: 支払日の土曜・日曜の調整と、12月分の年の繰り上がりが書かれている
- D10: 出力の並び順（申請番号、明細番号、社員番号の順）が書かれている
- D11: エラー処理で、引数の誤り（1）と入力データの不整合（2）を区別している
- D12: テストの方針として、境界値を挙げている
- D13: 要件（最終の決定）と矛盾する記述がない
