## Context
docs/requirements.md（議事録 第1〜4回・請求業務規程 9/1改定・連携仕様書 第4版を根拠に整理済み）をもとに、実装前の設計書を docs/design.md に書く。実装はしない（src/ は触らない）。
資料が食い違うときは **連携仕様書 第4版 ＞ 規程（9/1改定）＝第4回議事録 ＞ 第3回 ＞ 第2回 ＞ 第1回** の順で新しいものを採る。第1回の「送料無料 5,000円」「特約店 5%」「明細ごとの税切り捨て」、第3回の「注文がない顧客には発行しない」「並びは注文日・注文番号のみ」は置き換え済みとして設計に入れない。

## 設計書の構成と各節の要点（根拠）

1. **概要・前提** — 目的、範囲外（PDF）、Node.js 24・外部パッケージなし、入口 `src/cli.js`（仕様書 2・3章）。資料の優先順位を明記。
2. **モジュール構成**（src/ 配下、ESM、純粋関数中心で入出力は cli だけ）
   - `cli.js` 入口・終了コードの決定 / `args.js` 引数解析と検証 / `csv.js` CSV の読み書き（クォートなし、LF、末尾改行）
   - `loader.js` 6ファイル読込と型変換 / `validate.js` 不整合検査（全行、エラーを集める）
   - `period.js` 請求期間 / `pricing.js` 単価・特約店・数量割引・明細金額 / `shipping.js` 送料 / `returns.js` 返品金額 / `tax.js` 税額と端数処理 / `invoice.js` 顧客ごとの組み立て・発行判定・繰越 / `output.js` 並べ替えと CSV 化
   - 依存関係の図（テキスト）と各モジュールの公開関数の署名。
3. **データの流れ** — 引数検証 →（失敗: 終了1）→ 全入力読込 → 全行検査 →（不整合: 何も書かず終了2）→ 顧客ごとに期間算出 → 注文明細計算＋送料 → 返品 → 入金・前回請求額 → 税・合計 → 発行判定 → 並べ替え → 出力ディレクトリ作成・2ファイル書き込み → 終了0。中間データ構造（Customer, PriceRow, OrderLine, Order, Return, InvoiceLine, Invoice）を表で定義。
4. **計算の手順**（各手順に根拠と、サンプル C001 の値での検算例を添える）
   - 4.1 請求期間（規程4条）: 末日締め=対象月1日〜末日。日付締め d=前月d+1日〜対象月d日、1月分は前年12月。日付は UTC/文字列ベースで扱いタイムゾーンのずれを避ける。
   - 4.2 単価（規程5条、第4回決定1）: 同商品の行を valid_from 昇順で保持し、注文日以下で最大の行。税率・商品名も同じ行。
   - 4.3 特約店: `floor(単価×90/100)`（整数演算）。
   - 4.4 明細金額・数量割引（第3回決定1）: gross=単価×数量、数量≥100 なら 割引額=`floor(gross×5/100)`、金額=gross−割引額（`floor(gross×0.95)` ではない点を明記。例 110×100=11000→10450）。
   - 4.5 送料（第2回決定2、第3回決定2、別表）: 注文ごとに商品金額（割引後、8%含む）合計≥10,000 で無料、それ以外 A800/B1000/C1500、10%区分、`SHIPPING`/`送料` 行。返品で判定は変えない。
   - 4.6 返品（規程8条、第4回決定2）: 返品日が期間内のものを、元の注文の顧客の請求書へ。金額=`-floor(元金額×返品数量÷元数量)`（正で切り捨ててから符号）。単価・税率・商品名は元明細。例 10450×30/100=3135。
   - 4.7 消費税（規程7条）: 税率ごとに小計（10%は送料・返品込み）。税=小計×税率/100 を整数の分子・分母で計算し、顧客の方法（空欄=切り捨て、四捨五入は0.5以上切り上げ）で1回丸め。小計がマイナスなら絶対値で計算し符号を付ける。浮動小数を使わない。
   - 4.8 繰越（規程9条、第4回決定3・確認事項）: 前回請求額=balances の対象月の前月行のみ（なければ0、2か月以上前は使わない）。入金=入金日が期間内の合計。carried_over=前回−入金、total=小計10+税10+小計8+税8、total_due=carried_over+total。
   - 4.9 発行判定（第4回決定4）: 期間内の確定注文0件 かつ 返品0件 かつ 前回請求額0 かつ 期間内入金0件 なら出さない。
   - 4.10 出力の並び（仕様書 6章）: 請求書は顧客コード昇順。明細は請求書番号→日付→（注文が先: 注文番号昇順、注文内は受注データの行順、送料は注文の最後）→（返品: 返品番号昇順）。
5. **エラー処理**
   - 終了1: 引数不足・未知の引数・`--month` 形式不正（月 01〜12）。stderr に理由。
   - 終了2: 仕様書 3.1 の表の全項目。全行（期間外・取消含む）を検査し、見つかった不整合を**すべて**集めて stderr に1件1行（番号付き）で出し、出力ファイルは作らない（検査を書き込み前に完結させる）。返品数量超過は同じ明細の返品を 返品日→返品番号 の順に累積し、超えた時点の返品番号を示す。
   - 入力ファイルがない・見出しが違う・数値/日付が読めない場合も終了2として扱う（仕様書に明記がないため設計判断として記載）。
   - 出力ディレクトリ作成・書き込みの失敗は仕様書にないため、stderr に出して終了コード 3 とし、仕様書への追記を依頼する事項として記載する（下の「決める点」参照）。
6. **確かめ方（テスト方針）** — サンプル `docs/資料/data` で `--month 2026-09` を実行し、仕様書7章の invoices.csv 全行と C001 明細に一致すること。単体テスト（node:test）の観点: 期間（1月・2月・末日）、価格改定の境界日、特約店＋数量割引、送料の境界 9,999/10,000、返品の切り捨て、マイナス小計の税、各端数処理、各不整合と終了コード。
7. **未決事項・見送り** — 要件4章の見送り事項と、下記の設計判断。

## 設計で決める点（資料で解釈が分かれる箇所）
- 「前回の請求額もない」= 前月行がない **または金額0**。「入金もない」= 期間内の入金行が0件（合計0でも行があれば発行）。
- 返品の顧客は元の注文の customer_id。
- 返品数量超過の判定順は 返品日→返品番号。
- 不整合は最初の1件で止めず全件出す（担当者が一度で直せるように）。
- 入力ファイル欠落・形式不正は終了2。出力書き込み失敗は仕様外のため終了コード 3 とし、設計書で「仕様書に追記を依頼する事項」として挙げる。
- 金額計算はすべて整数演算（BigInt は不要な規模、Number の安全整数範囲で足りる旨を記載）。
