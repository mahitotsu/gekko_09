# 計画: docs/requirements.md（請求書発行システム 要件定義）の作成

## Context
docs/資料 の議事録4回分・請求業務規程（2026/9/1改定）・連携仕様書 第4版をもとに、請求書発行システムの要件を1つの文書にまとめる。議事録の途中で決定が変わっているため、最終の決定を要件とし、変更の経緯（どの回で何が変わったか）を別に示す。見送った要望は別の節に分ける。

## 資料の優先順位（食い違い時の扱い）
1. 新しい回の議事録の決定 ＞ 古い回の決定（第3回 確認事項で第1回のルールの置き換えを全員了承済み、第4回は第3回決定4を改めている）。
2. 連携仕様書 第4版・規程 9/1改定は第4回の決定を反映済みで、両者は最終決定と一致する。入出力形式は連携仕様書、計算規則は規程を根拠とし、規程にない事項（送料無料の基準＝規程6条2項で協議に委任）は議事録 第2回を根拠とする。
3. 第1回の議事録は「現行（手作業）のルール」として経緯にだけ載せ、要件には使わない。

## docs/requirements.md の構成と各節の要点（根拠）
1. **概要・目的・範囲** — 月末の手作業（300社超・3日）の自動化（第1回§1）。成果物は CSV（請求書・請求明細）のみ、PDF は対象外（第3回決定6）。9月分から適用・手作業と並行照合（第3回§4、第4回冒頭）。参照資料と版の一覧。
2. **用語** — 対象月、請求期間、締め日、特約店、明細の金額、繰越額、今回の請求金額(total)／今回の請求額(total_due) の区別。
3. **機能要件（最終決定）** 項目ごとに根拠を付記:
   - 請求の単位・請求書番号 YYYYMM-顧客コード（規程2条）
   - 締め日 1〜28 or 末、29〜31は扱わない／請求期間の求め方、1月分は前年12月から（規程3・4条、第2回決定1）
   - 対象注文: 状態「確定」かつ注文日が期間内（第3回決定3、規程4条3項）
   - 単価: 注文日時点で有効な商品マスタ行（valid_from が注文日以前で最新）、税率・商品名も同じ行（第4回決定1、規程5条1項）
   - 特約店: 単価×90%、1円未満切り捨て（第2回決定5、規程5条2項）
   - 数量割引: 明細の数量100以上で明細金額の5%引き、割引額切り捨て、特約店は特約店単価の金額に適用（第3回決定1）
   - 送料: 注文ごと、地域別 A800/B1,000/C1,500（規程別表）。無料基準＝注文の商品の明細金額（税抜、8%商品含む）合計が10,000円以上（第2回決定2）。送料は10%課税、送料行として出力、無料なら行なし（第3回決定2）
   - 消費税: 請求書ごと・税率ごとに合計して1回端数処理、方法は顧客ごと（切り捨て/四捨五入/切り上げ、空欄は切り捨て、四捨五入は0.5以上切り上げ）（第2回決定3・4、規程7条）。合計がマイナスなら絶対値で計算し符号を付ける（第4回決定5、規程7条4項）
   - 返品: 返品日の期間にマイナス計上、金額＝元明細金額×返品数量÷元数量の切り捨て、割引は元明細のまま、送料は返金せず送料判定も変えない（第4回決定2、規程8条）
   - 前回請求額・入金・繰越: 前月分のみ（2か月以上前は使わない）、行がなければ0、入金は入金日が期間内、carried_over＝前回−入金、total_due＝carried_over＋total（第4回決定3・確認事項、規程9条）
   - 請求書を発行する条件: 期間内に注文も返品もなく、前回請求額も入金もない顧客のみ発行しない（第4回決定4）
   - 入力データの不整合: 連携仕様書3.1の表をそのまま要件化。対象期間外・取消も検査、1件でもあれば出力なし・終了コード2、番号をメッセージに含める（第3回決定5、第4回決定1・2）
4. **入出力・インターフェース要件** — コマンド・引数・終了コード、6入力ファイル、2出力ファイルの列、CSV形式（UTF-8 BOMなし、LF、末尾改行、クォートなし）、並び順（顧客コード順／請求書番号→日付→同日は注文(注文番号順、行順、送料は注文の最後)→返品(返品番号順)）。列定義は連携仕様書の表を要約し、詳細は仕様書を参照とする。Node.js 24・外部パッケージなし・src/cli.js。
5. **決定の変更履歴** — 表形式（項目／変更前（回）／変更後（回）／理由）:
   - 締め日: 全社末日（第1回）→ 顧客ごと（第2回）
   - 送料無料基準: 5,000円（第1回）→ 10,000円（第2回、10月価格改定に合わせ営業と合意）
   - 特約店割引: 5%（第1回）→ 10%・単価で切り捨て（第2回、7月契約変更）
   - 消費税: 明細ごと切り捨て（第1回）→ 請求書・税率ごとに1回、端数処理は顧客ごと（第2回、インボイス制度）
   - 送料の消費税: 10%課税のみ確認・詳細保留（第2回）→ 送料行・10%に含める（第3回）
   - 数量割引: 第2回宿題 → 導入（第3回）
   - 取消注文の混入防止: 要望（第1回）→ 確定のみ対象（第3回）
   - 請求書を発行しない条件: 対象注文なし（第3回決定4）→ 注文・返品・前回請求額・入金すべてなし（第4回決定4）
   - 商品価格: 単一価格 → 適用開始日つき複数行（第4回）
   - 返品・前回請求額・入金: なし → 追加（第4回）、マイナス金額の税（第4回）
   - 不整合検査: 顧客・商品（第3回）→ 有効価格なし・返品・入金・前回請求額を追加（第4回）
   - 連携仕様書 第1版（第2回、3入力2出力）→ 第3版（第3回）→ 第4版（第4回、6入力）
6. **見送り・対象外の要望**（要望者・回・理由）:
   - 税込/税抜表示の得意先ごとの切替（佐藤部長 第1回 → 第2回見送り、インボイスで税率ごとの税抜額と税額を必ず記載するため）
   - 送料を重量で決める（営業 → 第3回見送り、商品マスタに重量がない）
   - PDF 出力（田中課長 第1回 → 第3回で範囲外、次期で検討）※「見送り」ではなく「範囲外・次期検討」と明記
   - 返品時の送料返金（営業 → 第4回見送り）
   - 入金の請求書ごとの消し込み（鈴木 → 第4回見送り、顧客ごとの差額繰越のみ）
   - 返品の元期間への遡及修正請求書（第4回見送り）
7. **未確定・確認が必要な点**（資料に明記がないもの。要件として断定しない）:
   - 送料無料判定の「商品の金額」は特約店・数量割引の後の金額と解釈（規程5条3項の「明細の金額」の定義による）。サンプルではこの差が出る注文がないため確認を推奨。
   - 返品数量超過の「超えた時点」を決める返品の順序（返品日順か返品番号順か）。
   - 繰越額や今回の請求額がマイナス（過入金・返品超過）になる場合の扱い（出力はマイナスのまま出すと読めるが明記なし）。
   - 同一顧客・同一月の balances.csv 重複行の扱い。
8. **受け入れの確認** — 連携仕様書7章のサンプル出力（data/ で --month 2026-09）と一致すること。例で確かめられる規則（C002: 8/21注文に旧価格2,380、特約店99円・数量割引11,286円／C005: 期間外のO1009除外／C003: 取消O1013除外／C007: 前回請求額と入金のみで発行）を挙げる。

## 漏れやすい観点（書くときのチェック）
- 29〜31日締めを扱わない、1月分の期間、期間の初日・末日を含む
- 送料無料は「以上」、8%商品も基準に含める、返品があっても送料判定を変えない
- 返品行の商品名・単価・税率は元の注文日時点のもの
- 不整合検査は期間外・取消の行も対象、出力ファイルを作らない
- total と total_due の違い

## 手順
1. 上の構成で docs/requirements.md を Write で作成（日本語、根拠を「（第2回 決定2）」「（規程 第7条）」「（連携仕様書 3.1）」の形で各要件に付記）。
2. 変更履歴と見送りが漏れなく議事録と対応しているか、各議事録の「決定事項」「見送り」「確認事項」を読み直して突き合わせる。

## 確かめ方
- 議事録4回の決定・見送り・確認事項の各項目が、文書のどこかに1回ずつ対応しているかを照合する。
- 数値（5,000→10,000円、5→10%、100個・5%、送料額、番号形式）を資料と照合する。
- 例の数値（C001・C002 など）を文書内に書く場合は手計算で連携仕様書7章と一致を確認する。
