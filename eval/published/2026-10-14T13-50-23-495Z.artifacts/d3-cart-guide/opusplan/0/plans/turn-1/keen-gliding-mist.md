# 計画: docs/cart-guide.md（Cart 利用者向けガイド）

## Context
`src/cart.js` の `Cart` を使う開発者向けの説明文書を新しく作る。対象は公開メソッドの使い方、金額計算の順序、使うときの注意点の3つ。**コードは変更しない**（src/・test/ には触れず、`docs/cart-guide.md` を1ファイル新規作成するだけ）。

根拠にする資料: `src/cart.js`、`src/money.js`（addTax, formatYen）、`src/config.js`（TAX_RATE=0.1, MAX_CART_ITEMS=50）、`test/basic.test.js`（使用例: 100×2 + 300 → subtotal 500, total 550）。

## 方針（資料どうしが食い違うときの扱い）
- **文書には実装の実際の動きを書く**。コメントや仕様と食い違う箇所は「注意」として明記し、どちらが正しいかは決めつけない。
  - `money.js` のコメントは「Spec: round half up（四捨五入）」だが、実装は `Math.floor`（切り捨て）。→ 実際は切り捨てになると書き、コメントと食い違っていることも書く。
  - `add()` の上限チェック（下記）も、意図と違うように見えるが、現在の動作として書く。
- 推測で書かない。下の検証手順で挙動を確認できたことだけを書く。

## 構成と各節の要点
1. **概要** — 金額は円の整数・税抜きで渡す前提。import 例（`import { Cart } from './src/cart.js'`）。
2. **クイックスタート** — テストと同じ例（a:100×2, b:300 → subtotal 500, total 550, receipt "合計 ¥550"）。
3. **公開メソッド**（シグネチャ・引数・戻り値・例外）
   - `add(sku, price, qty = 1)` — 同じ sku を2回目に add すると数量が加算され、**価格は最初の値のまま**で2回目の price は無視される。合計数量が `MAX_CART_ITEMS`(50) を超えると `Error('cart is full')`。
   - `remove(sku)` — 行ごと削除する（数量を減らすのではない）。存在しない sku でもエラーにならない。
   - `count()` — 全行の数量の合計。
   - `applyCoupon(code, percent)` — 割合の割引。外す API はない。
   - `subtotal()` — Σ price×qty（税抜き・割引前）。
   - `total()` — 税込み・割引後の整数円。
   - `receipt()` — 現状は `合計 ¥X` の1行だけ（明細は出ない。コードに TODO がある）。
   - `lines` / `coupons` プロパティは内部状態なので直接書き換えないこと（チェックが働かなくなる）。
4. **金額の計算の順序**（`total()`）
   1. subtotal = Σ price×qty
   2. クーポンを適用した順に `amount *= (1 - percent/100)` → **複利的に掛かる**（10% と 10% で 20% 引きではなく 19% 引き）。途中で丸めない
   3. `Math.round` で円に丸める（四捨五入）
   4. `addTax`: `Math.floor(amount × 1.1)`（**切り捨て**）
   - 数値例を1〜2個つける（例: 1000円・10%クーポン×2 → 810 → 891）。
5. **注意点**
   - 同じクーポンコードを2回 apply すると2回効く（重複チェックがない）。
   - 入力の検証がない: 負の qty・0・小数の価格、percent>100（合計がマイナスになる）、percent<0 も通ってしまう。
   - **既存の sku に add するときの上限チェック**: `line.qty += qty` がチェックより先に実行され、しかも既存の行は Map 内の同じオブジェクトなので、(a) 新しい数量が二重に数えられ、50 より手前で `cart is full` になる、(b) 例外が出ても数量の加算は残ったままになる。新しい sku ではこの問題は起きない。
   - 税の丸めが切り捨てで、money.js のコメント（四捨五入）と合わない。
   - 税率と上限は `src/config.js` の定数で決まり、インスタンスごとには変えられない。
   - 空のカートは total 0、receipt "合計 ¥0"。

## 手順
1. 実行の前に node で挙動を確かめる（読むだけで、ファイルは作らない）:
   - 既存 sku の上限: `add('a',100,30); add('a',100,15)` → 例外が出るか、その後の count が 45 になっているか。新しい sku だと `add('b',100,15)` は通るか
   - 2回目の add で価格が変わらないこと／クーポンの複利（1000→891）／105円 → 115（切り捨て。四捨五入なら 116）／percent 150 で負の値になること／空のカート
   - 確かめた結果と違う記述があれば、文書の方を直す。
2. `docs/` を作り、`docs/cart-guide.md` を上の構成で日本語で書く。
3. 文書中の数値例を node で計算し直して照合する。`npm test` が通ること（コードを触っていないことの確認）。
