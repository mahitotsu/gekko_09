# 測定の結果

`opusplan`（計画は Opus、実行は Sonnet）を CLAUDE.md で運用したときに、Opus 単独と比べて何が得られ、何を失うかの測定。結論は [README](../README.md) にある。ここには方法、結果の表、未確認、公開した結果ファイルの対応表を置く。

## 方法

- **環境**: Claude Code 2.1.295 / Agent SDK 0.3.295。コンテナ内で、実行ごとに空の HOME と設定を使い、ホストの設定・skills・MCP・メモリを持ち込まない（[eval/env.ts](../eval/env.ts)）。認証はサブスクリプションの OAuth トークンだけ。応答は日本語。価格は定価（Opus 5.5 $4 / $20、Sonnet 5.5 $2 / $10、Haiku 5.5 $0.10 / $0.50、1M トークンあたり入力 / 出力。キャッシュ読み取りは Opus $0.20、Sonnet $0.10）で、トークン数から再計算した（[eval/cost.ts](../eval/cost.ts)）。SDK の `total_cost_usd` は使わない（下の「費用の訂正」）。表の費用は、実際に課金されたキャッシュの状態のまま計算した値（`report.ts` の `cost`、measured）。通し auto の費用比は、cold（外のキャッシュなし）で 0.57 倍、warm（共通の接頭辞が既にキャッシュ済み）で 0.53 倍で、measured の 0.55 倍と大きく変わらない。サブスクリプションでは請求額ではなく、定価に換算した利用量。
- **比較対象（arm）**: `opus`、`sonnet`、`haiku`、`opusplan`。`opusplan` は、モデルの指定 `opusplan` に、[examples/user/CLAUDE.md.example](../examples/user/CLAUDE.md.example) を作業ディレクトリの CLAUDE.md として置く。人がいないので、`EnterPlanMode`・`ExitPlanMode` と計画ファイルへの書き込みだけを許可し、ほかは拒否する。
- **課題**: [eval/tasks.ts](../eval/tasks.ts)。小さな課題（質問、1か所の修正、設計や説明の文書）と、invoice シナリオ（議事録・規程・仕様書から、要件定義、設計書、実装、テスト、報告書を作る。`script` は段階ごとの会話、`auto` は1回の依頼、`stage-N` は1段階だけ）。
- **採点**: 質問は返答の要点の一致（数値、または必須の要点2つ）。修正と実装は隠したテスト。文書は採点基準の項目ごとに、判定役のモデルが、実行名を伏せて 0/1 で採点（[eval/grade-docs.ts](../eval/grade-docs.ts)）。文書の比較は、判定役 Sonnet が順番を入れ替えて2回比べ、**2回が一致したときだけ勝ち**とする（[eval/compare-docs.ts](../eval/compare-docs.ts)）。
- **時間**: API 時間（`duration_api_ms`）。
- **「入った」の判定**: その実行に Opus のステップがあること（`opusplan` では計画中だけ Opus が応答する）。

## 結果

### 仕組み

- 文書・通しの依頼 20 回（invoice の stage-1・2 各5回、auto 3回、script 1回、設計・説明の文書 d1・d3・d4 各2回）は、すべて計画モードに入った。質問と1か所の修正 16 回（e2・e4・q1・q2・j1・j2）は一度も入らなかった。
- 流れは、Sonnet が `EnterPlanMode` を呼ぶ → 計画中は Opus → `ExitPlanMode` の後は Sonnet。
- 計画には、構成、各節の要点と根拠（資料のどこか）、資料が食い違うときの採り方、漏れやすい観点、確かめ方まで書かれた（[eval/published/](../eval/published/) の `plans/`）。通し（auto）の計画には、モジュールの設計とテストの観点まで入っていた。
- 切り替えのたびに、会話の分をキャッシュに書き直す。会話が 15K トークンなら Sonnet への切り替えで約 $0.06、100K なら Sonnet へ約 $0.40、Opus へ約 $0.80（定価からの試算）。

### 質問

| 課題 | `opusplan` | Opus 単独 |
|---|---|---|
| e2・e4（場所・数を答える） | 全回入らず、$0.02〜0.03、約 4〜6 秒 | $0.04〜0.06、約 4〜8 秒 |
| q1・q2（コードを追って数値を答える） | 全回入らず、$0.04〜0.05、時間 約 10 秒 | $0.07〜0.09、約 11〜16 秒 |
| j1・j2（原因の説明、修正方針の判断。必須の要点2つ） | 全回入らず、6/6、$0.03〜0.05、約 8〜9 秒 | 6/6、$0.06〜0.09、約 12〜15 秒 |

- 費用は Opus 単独より約 4〜5 割低い（課題ごとに中央値で 36〜51%、平均で 40〜59%。平均は e2 の Opus の外れ値 $0.13 で押し上がる。Sonnet が答えるため）。
- 時間は Opus 単独の 0.6〜0.9 倍。e2 だけは同程度（`opusplan` 6.0 秒と 3.8 秒に対し、Opus 4.3 秒）。
- q1 の `opusplan` 1回は、「数字だけ」の指示を守らず不合格にした（答えは正しい）。
- j2 で、Opus 単独は3回とも「足したあとの `count()` にさらに `qty` を加える二重加算」という別の欠陥に触れた。`opusplan` は3回中1回。要点が決まった質問では差が出ないが、「ついでに別の欠陥に気づく」では Opus が上回る傾向がある（標本は小さい）。

### 文書（invoice の stage-1 要件定義・stage-2 設計書）

- 採点は全件満点（要件定義 22/22、設計書 14/14）。
- 比較（`opusplan` 5回、Opus 3回、Sonnet 1回）: 対 Opus は 14 組中、Opus の勝ち 2、`opusplan` の勝ち 0、残りは割れか引き分け。対 Sonnet は 6 組中、`opusplan` の勝ち 2（要件定義）、Sonnet の勝ち 2（設計書）、残りは割れ。
- 費用（平均）・時間（中央値）: stage-1 は `opusplan` $0.65・118 秒、Opus $0.59・132 秒。stage-2 は `opusplan` $0.74・160 秒、Opus $0.66・181 秒（Opus の1回は 321 秒で外れ値）。費用は Opus 単独の約 1.1 倍、時間はほぼ同じ。
- 文書は Opus に近づくが並ばない。参考に、Sonnet 単独が書いた文書は Opus 単独に負ける（8 組中 Opus の勝ち 7、割れ 1。判定役 Sonnet。`2026-10-11T05-52-29-193Z.compare.claude-sonnet-5-5.jsonl`）。

### 通し（invoice）

| | 結果 | 費用 | API 時間 |
|---|---|---|---|
| auto: `opusplan`（3回） | 3/3 合格 | 中央値 $1.54（$1.34〜1.56） | 中央値 413 秒（368〜449） |
| auto: Opus 単独（3回） | 3/3 合格 | 中央値 $2.79（$2.41〜2.85） | 中央値 676 秒（522〜768） |
| auto: Sonnet 単独（1回） | 合格 | $1.22 | 435 秒 |
| script: `opusplan`（1回） | 不合格 | $3.90 | 720 秒 |
| script: Opus 単独（1回） | 合格 | $4.01 | 909 秒 |
| script: Sonnet 単独（1回） | 合格 | $1.22 | 412 秒 |

- auto の `opusplan` は、Opus 単独の 0.61 倍の時間、0.55 倍の費用。計画モードに入るのは最初の1回だけで、あとはすべて Sonnet。
- 同じ auto で、Sonnet 単独（1回）も合格し、費用は `opusplan` の 0.79 倍（逆に言えば、`opusplan` は Sonnet 単独の 1.26 倍）、時間は同程度だった。通しの成果物の質は採点では分けられていない（合否のみ）。
- script の `opusplan` が落ちたのは、うるう年でない年の3月の請求期間（`nonLeapMar`）。Haiku の script も同じテストで落ちた。1回なので、偶然か、段階ごとの計画に実装の細部が足りなかったかは分けられない。script で計画モードに入ったターンの数は、初版に「4ターン」と書いたが、公開した結果には計画ファイルがなく、確認できない（Opus のステップは 12 で、auto の `opusplan` と同数）。

### CLAUDE.md の入る基準の調整

候補（入る・入らないの条件の部分だけが違う）:
- A（現在）: 新機能・複数ファイル・設計の判断・文書の作成は入る。質問・1か所の修正・短い続きは入らない。迷ったら、文書なら入る。
- B: 成果物が複数／資料が複数／設計の判断のどれかに当たれば入る。当たらなければ入らない（「迷ったら文書なら入る」をやめる）。
- B2: B の条件に「当たる可能性が少しでもあるなら入る」を使い、質問・1か所の修正・短い続きは迷っても入らない。

計画までで止める形（`ExitPlanMode` を拒否）で、入った回数を数えた。課題は、入るべきもの（invoice の stage-1・stage-2・auto、d1、d4）、入らないもの（e2・e4・q1・q2・j1・j2・m1・s1）、境目（d3: 既存コードを説明する単一の文書）。

| | 開発用の課題（15 回） | 取っておいた課題（12 回） |
|---|---|---|
| A | 13/15 | **12/12** |
| B | **15/15** | 11/12 |
| B2 | 13/15 | 測らず |

- 開発用で B が良かったのは d3 だけ（A・B2 は2回とも入り、B は入らなかった）。取っておいた課題では、B が d4（設計の判断が要る単一の文書）で1回入りそこねた。
- 事前の採用基準（開発用で A を 10 ポイント以上上回り、取っておいた課題で A を下回らない）を B は満たさず、A のままとした。
- 質問や1か所の修正の課題は、どの書き方でも 40 回すべて入らなかった。B2 の「可能性が少しでも」でも、入りすぎは起きなかった。

### 採らなかったもの

- **ターンの途中でメインのモデルを切り替えるルーター**（難易度の判定で Opus / Sonnet / Haiku を切り替える mod）。小さな課題 18 件では、Opus 単独より合計コストが 58%、合計レイテンシが 34% 低かった（効果の大部分は、軽い依頼を Haiku に回したこと）。しかし、会話が長いほど切り替えが高くつくこと（上の「仕組み」）と、文書の質は Opus が書いたときにしか出ないこと（文書の節と、見直しの項）から、作り込まないと判断した。実装は削除した。生データは公開しない。この費用は、SDK の `total_cost_usd` による値（下の「費用の訂正」）。ルーターは Sonnet も使うため、Sonnet の分が高く出ており、58% は控えめな値のはずだが、生データがなく再計算していない。
- **Sonnet のサブエージェント**（調べ物を任せる）。invoice stage-1 で、Opus 単独 $0.59・132 秒に対し $0.97・292 秒。新しい文脈の立ち上げとキャッシュの書き込みが、単価の差を打ち消した。Pro プランでは、ユーザーが求めないとサブエージェントは起動されない。
- **Sonnet が書いた文書を Opus が見直す**。見直した後も、Opus が書いた文書に負けたままだった（8 組中 Opus の勝ち 6、割れ 2。`2026-10-11T05-52-29-193Z-review.compare.claude-sonnet-5-5.jsonl`）。

## 費用の訂正（2026-10-17）

この文書の初版は、Sonnet を使う実行（`opusplan`、Sonnet 単独）の費用に、SDK の `total_cost_usd` を使っていた。SDK の内蔵の価格表は Sonnet 5.5 のキャッシュ読み取りを $0.20/MTok と数えるが、[公式の価格表](https://platform.claude.com/docs/en/about-claude/pricing)は $0.10（[eval/cost.ts](../eval/cost.ts) の冒頭にも注記がある）。Opus・Haiku の実行は差がない。Sonnet 単独の通し（script）は、SDK $1.399 に対し、トークン数からの再計算で $1.217。差 $0.182 は、キャッシュ読み取り 1.82M トークン × $0.10 と一致する。

原因は、SDK（Claude Code のバイナリ）に埋め込まれたモデルカタログで、Sonnet 5.5 が Sonnet 5 と共通の価格の枠（`tier_2_10`、読み取り $0.20）に入っていたこと。Opus 5.5 は専用の枠（読み取り $0.20、公式の 0.05 倍）だった。最新の 0.3.302 では、Sonnet 5.5 の専用の枠（`tier_2_10_cache_read_0_10`、$0.10）になっている。どの版で直ったかは 0.3.296〜0.3.302 の間で、特定していない。**古い SDK / Claude Code を使うと、ログ（`total_cost_usd`、/cost の元の値）は古い価格のままになる。** 版を上げると、ログの値も公式に近づく。このリポジトリの依存は 0.3.302 に上げた。測定は 0.3.295 で行ったままで、やり直していない。

全表を、公開した結果ファイルから再計算した値に直した。

| 項目 | 訂正前 | 訂正後 |
|---|---|---|
| 通し auto の費用比（`opusplan` / Opus） | 0.61 倍 | **0.55 倍**（時間は 0.61 倍のまま） |
| 通し auto `opusplan`（中央値） | $1.69 | $1.54 |
| script `opusplan` | $4.25 | $3.90 |
| Sonnet 単独の通し | $1.40 | $1.22 |
| 質問の費用の低さ（対 Opus） | 25〜75% | 約 4〜5 割（中央値 36〜51%、平均 40〜59%） |
| 小さな文書の費用比 | 1.7〜1.8 倍 | 1.6〜1.8 倍 |
| 要件定義・設計書の費用比 | 1.1〜1.15 倍 | 約 1.1 倍 |

時間、採点、比較、計画モードに入った回数は、費用を使わないので変わらない。
